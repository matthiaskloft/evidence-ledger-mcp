# Tool reference

Details of the tools listed in the [README](../README.md#tools).

## Exports and summaries

`export_ledger` defaults to `level="full"`, `format="jsonl"` and excluding withdrawn records. Keep full exports private. Use `level="masked"` with optional `max_words` (1–25) for excerpts, or `level="locator"` to remove quoted source text. Exports retain other record metadata, including `note` and header `notes`, and always remove `locator.chunk`. A publication check rejects copied source text in other metadata at masked and locator levels; it does not replace publication approval. The output must be a new file.

Masked exports accept `max_words` from 1 to 25. With a focus they keep a centred window, shifting at the quote edges to use the budget; otherwise they keep the start and end. Cuts are marked with “…”; quotes shorter than the budget stay whole. A focus longer than the budget is refused. Without `max_words`, masking still keeps only the first and last words (at most three each and half the quote), even with a focus. The export header records `level` and `max_words`.

`summarize_ledger` writes a self-contained HTML report grouped by claim, with `full`, `masked` and `locator` levels. Print it from a browser to produce a PDF; the server does not write PDFs directly. Masked summaries use the default start/end masking and do not accept `max_words`.

## Embedding

`embed_ledger(path, work, out, level, layout, include_withdrawn)` takes the HTML of the work (rendered by Quarto, Pandoc or any tool) and writes a copy to a new file in which each claim's `anchor.exact` text is marked and followed by its claim ID, linked to an evidence card. Layout `endnotes` collects the cards in an "Evidence" section before `</body>`. Layout `panel` keeps that section and, with JavaScript, also opens a clicked mark's card in a fixed side panel (a sidebar from 1100 px width, where the first claim's card is open at load; a bottom sheet on narrower screens). Enter opens a mark, the left and right arrow keys step through the claims and, on narrow screens, Esc closes the sheet. Without JavaScript the page shows the end section only. If no anchor is located, `panel` falls back to `endnotes` and the result's `layout` says `endnotes`. Anchor text is matched after normalising curly quotes, dashes and ellipses, and a match on word boundaries is preferred. Anchors that have only a marker, are not found, or overlap text already marked for another claim go into a "Not located in the work" list (an overlapping one notes "overlaps C-xxxx") and are returned in `not_located`; `overlapping` maps each such claim ID to the claim it overlaps. When a located claim has records whose anchors differ, the card lists the others. A record's key links to `#ref-<key>` when the work has that element (as Pandoc and Quarto emit); otherwise the DOI or URL link remains. Levels and the publication check work as for `summarize_ledger`; unlocated anchors show no work text at the `masked` and `locator` levels. The work's text is not changed apart from the marks, claim-ID superscripts and an end section, but the output sets its own page-wide light/dark theme (following the system setting) and adds a hint line for `panel`; the added styles use `el-` class names. `out` must be in the same folder as the work, so relative links to figures, styles and scripts still resolve. The output is UTF-8: a charset the work declares is changed to `utf-8`. A `full` result holds whole quotes: keep it private.

## Checks

`check_ledger(path, work, revision, bibliography, sources, include_withdrawn, source_urls)` reads the ledger and writes nothing. Its result holds record IDs, claim IDs, keys and counts, never quote or source text, so it can be shown or logged anywhere. `records` counts the records checked and `claims` their distinct claim IDs; withdrawn records count only with `include_withdrawn`. `gaps` is always returned: `missing_evidence` maps each contestable record to the fields among `locator`, `quote` and `justification` that it lacks, and `claims_without_records` lists claims whose records are all withdrawn (whatever `include_withdrawn` says). The other checks run when their input is given. `work` is a path (HTML, Markdown, Quarto, LaTeX or plain text); `anchors` counts the anchors checked and lists records whose `anchor.exact` text is not found (`not_found`; HTML is matched as in `embed_ledger`, on the visible text. Other files are matched against their source text, after collapsing whitespace and typography, so markup inside an anchor, such as emphasis, a link, `\emph{}` or `[@key]`, reports `not_found`; check anchors against the rendered HTML where you can) and those with only a marker (`marker_only`). `revision` lists records whose `provenance.manuscript_rev` differs (`different`) or is missing (`unknown`). `bibliography` is a `.bib` or CSL JSON file; record keys missing from it are listed under `gaps.keys_missing_from_bibliography`. Without one, the `ref-<key>` entries of an HTML work serve, if it has any. `sources` maps a record `key` to the source's full text, which the agent supplies; each quote is compared after n2 normalisation and listed as `matched`, `not_found` or `no_source`. `matched` means the quote's letters and digits appear in order in the source, since n2 ignores spacing, punctuation and word boundaries. Records without a quote are left out of `quotes`. `source_urls` maps a record `key` to a public `http` or `https` URL whose text the server fetches itself and adds to `sources` (a key in both is an error). HTML is reduced to its visible text; plain text is used as is; a PDF (served as `application/pdf` or `application/x-pdf`, or as `application/octet-stream` with a PDF header) is reduced to the text of its pages, in a separate process stopped after 15 seconds; scanned, password-protected (a permissions-only owner password is fine), unreadable, too slow and over-long PDFs (more than 2000 pages or 20 million characters) fail, and a word hyphenated across lines can make a quote `not_found`; other types fail. The server refuses hosts that resolve to non-public addresses (loopback, private, link-local), on every redirect too (at most 5), allows 15 seconds per download in total (redirects included; the DNS lookup is not timed) and reads at most 10 MB. A fetch that fails does not raise an error: `quotes.fetch_failed` maps its key to a short reason (such as `non-public address`, `too large`, `HTTP 404`, `timeout` or `no text in pdf`), and the records of that key count as `no_source`. Fetched text is not returned or stored. Withdrawn records are skipped unless `include_withdrawn` is set.

## Link resolution

`resolve_links(path, folder, link_file, bibliography, include_withdrawn)` resolves the ledger's sources against the reader's own PDFs, so that a recipient can confirm records without the author's files. `folder` is searched recursively for `.pdf` files (at most 5000; files over 200 MB are skipped). File names do not matter: a source is matched by the first of its DOI on a PDF's first two pages, its ISBN on the first ten, and its title on the first two (letters and digits only, so case, punctuation and line breaks do not matter; a title under 20 characters counts only together with the first author's family name from the bibliography, as for `Mistral 7B`). Each must point to exactly one PDF, and only the first pages are read, so that a PDF which merely cites the source in its references does not match. DOI and ISBN come from the records and, with `bibliography` (a `.bib` or CSL JSON file), from the source's entry, which also supplies the title. Only when none of these match is a PDF named after the `key` (case-insensitive, e.g. `smith2020.pdf`) used; failing that, a PDF whose name holds the first author's family name and the year from the bibliography, in any order and separated in any way (e.g. `Smith 2020.pdf`, `smith_2020_title.pdf`, `2020-Smith.pdf`). Either must be the only such PDF, so two papers by one author in one year match neither. Text is extracted as in `check_ledger`, in a separate process stopped after 15 seconds per file. Reading PDFs stops after 300 seconds per call; PDFs not read by then are counted under `time_limit.files_not_read`, and their sources may show as `source_not_found`, so a very large folder (such as a whole Zotero storage folder) is better narrowed down. DOIs may carry a `doi:`, `https://doi.org/` or `http://dx.doi.org/` prefix.

Each record then gets one status:

- `found`: a passage in the PDF hashes to the record's `quote_hash` (n2, or legacy n1). This confirms the record independently. Whitespace, punctuation and case may differ; line-end hyphens and ligatures disappear in normalisation. A whole quote is also found when a page break splits it and the PDF's text puts running heads, footers, captions or a sidebar between its two parts; the link file then marks it `across_pages`. The gap must contain a page break, so a quote that silently leaves out words within a page is not found. A masked quote cannot be followed across a page break.
- `passage_not_found`: the source matched, but no passage did.
- `source_not_found`: no single PDF matched the source's DOI, ISBN, title or key.
- `not_searchable`: the record has no quote to start from, its `quote_hash` is neither n1 nor n2, or its masked quote has no first or last words: a `masked` export with `max_words` and a `quote_focus` keeps only words from the middle (`… words …`), and the hash covers the whole quote, so its start and end cannot be found. A quote is first tried whole, so one that itself opens or closes with an ellipsis is searchable; a masked quote whose first and last words are too common to tell its passage apart (over 20,000 candidate spans) counts as `passage_not_found`. A whole quote works, and so does a quote masked to its first and last words, as `masked` exports keep it; a `locator` export carries only the hash, which cannot be searched yet.

The result is written to `link_file`, which must be named `*.private.json`: the ledger and folder paths, and for each record its status, the matched file and a page, with `page_from` saying where it came from (see below). A rerun replaces a link file this tool wrote; any other existing file is left alone and the call fails. The link file holds paths on the reader's computer; keep it there and do not share it. The tool returns the record IDs per status, the link file path, `unreadable_files` (each PDF that could not be read, with a short reason such as `unreadable pdf`, `encrypted pdf` or `pdf too slow`) and, if the time ran out, `time_limit`; it never returns source text. Withdrawn records are skipped unless `include_withdrawn` is set.

Where no passage is found but the PDF matched, the link file still gives a page, taken from the record's `locator.page`. The ledger's page is the printed page number (an article on pp. 345–360 cites `347`), so it is looked up in the PDF's printed page labels when the PDF has them (`page_from: page_label`); without labels it is used as the PDF page number (`page_from: page_number`), which is right only where the two coincide, as in most preprints and books. A page found from the passage has `page_from: passage`.

## Private relinked copies

`relink_html(html, folder, bibliography)` gives a reader, such as a co-author who received a summary or embedded HTML, links from it to their own PDFs. Files written by `summarize_ledger` and `embed_ledger` carry a small JSON block (`<script type="application/json" id="evidence-ledger-data">`, which the browser does not run) with each record's `id`, `key`, `doi`, `isbn`, `url`, `locator`, `quote` and `quote_hash`, at the export's level and after its publication check; anchors, notes and other fields stay out. `relink_html` reads that block, matches the sources in `folder` as `resolve_links` does, and writes a copy next to the original, named `<name>.private.html` (a rerun replaces a copy this tool wrote, but no other file of that name; the original is never changed). Each evidence card gets a "Your copy" line linking to the PDF at the page of the passage, or else at the cited page as above, saying which.

The copy is private: its links are paths on this computer. It says so in its file name, its title (`[Private] …`), a banner at the top and a `noindex` tag, and the tool's result carries the same notice. Share the original, never the private copy. When the PDFs are inside the copy's folder, the links are relative (`pdfs/smith2020.pdf#page=3`), so a team sharing one project folder, for example in a synced drive, can each open them; otherwise they are absolute `file://` links that work only on this computer. Browsers open these links when the copy is opened from disk, not from a website. A private copy cannot be relinked again; relink the original. Files written before this version carry no data block: rebuild them with `summarize_ledger` or `embed_ledger`.
